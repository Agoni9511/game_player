## 1. 交接结论

项目已经完成管理后台、RBAC、陪玩师资料、商品与套餐、订单、派单接单的基础闭环。当前适合继续开发陪玩师端，不建议立即接真实支付。

```text
用户/角色/权限
  → 游戏、位置、标签
  → 陪玩师入驻资料与审核
```

### 3.2 Windows 启动命令

在项目根目录打开 PowerShell：

```powershell
. .\use-tools.ps1
```

```powershell
Set-Location .\backend
$env:ADMIN_INITIAL_PASSWORD='仅首次初始化时使用的强密码'
mvn spring-boot:run
```

```powershell
Set-Location .\art-design-pro
```

## 5. 已完成功能

### 5.1 RBAC 与系统管理

- 用户新增、编辑、启用、禁用、重置密码
- 用户分配角色
- 角色新增、编辑、启用、禁用、删除
- 角色分配目录、菜单和按钮权限
- 菜单、目录、按钮权限 CRUD
- 菜单图标选择
- 登录日志和操作日志
- 禁止删除或禁用最后一个超级管理员
- 接口使用具体权限编码校验，不只判断 admin 角色
- 前端动态菜单和按钮权限隔离

核心权限编码示例：

```text
system:user:create
system:user:update
system:role:assign
business:product:create
business:order:status
business:dispatch:respond
```

### 5.2 游戏与陪玩师

- 游戏 CRUD、启停
- 游戏位置维护
- 陪玩师标签维护
- 陪玩师资料、游戏资料、擅长位置、主位置
- 头像、封面、段位证明、照片、视频、语音等媒体资料
- 陪玩师审核
- 工作状态管理
- 审核和工作状态日志
- 三角洲行动、无畏契约演示数据

主要业务规则：

- 只有审核通过且启用的陪玩师可以进入可接单状态
- 已被陪玩师使用的位置不能删除
- 游戏被陪玩师或商品使用时不能直接删除
- 上架商品引用的游戏不能禁用

### 5.3 文件上传

- 统一上传接口：`POST /api/file/upload`
- 本地保存目录：`backend/data/uploads/年/月/`
- 数据库只保存 `/uploads/...` 地址
- 支持图片、视频、音频和 PDF 证明材料
- 默认最大 20MB
- 上传需要登录并记录操作日志
- 前端统一上传组件支持预览、更换、移除和手填地址

存储接口已经抽象为 `FileStorage`。未来切换 OSS 时新增 OSS 实现即可，不要修改业务表字段。

### 5.4 商品与套餐

商品统一采用 SPU/SKU 模型：

- `SERVICE`：单项服务
- `PACKAGE`：平台套餐

已实现：

- 商品分类树
- 基础服务 CRUD
- 商品 SPU CRUD
- 多 SKU、售价、划线价、计价单位、购买范围、库存、服务时长
- 草稿、上架、下架
- 平台套餐组合多个基础服务
- 套餐服务数量和计量单位
- 套餐有效天数和每人限购
- 商品复制并自动生成新编码
- 游戏、分类、服务和 SKU 完整性上架校验

主要规则：

- 单项服务必须绑定一个基础服务
- 平台套餐至少包含两个不同基础服务
- 商品只能选择末级分类
- 商品、分类和基础服务必须属于同一游戏
- 至少存在一个启用 SKU 才能上架
- 上架商品禁止直接编辑和删除
- 被上架商品引用的分类或基础服务不能禁用
- 被商品引用的分类或基础服务不能删除

### 5.5 编码自动生成

新增时由前端自动生成，仍允许人工修改和重新生成：

- 游戏编码
- 游戏位置编码
- 标签编码
- 分类编码
- 基础服务编码
- 商品编码
- SKU 编码

工具文件：`art-design-pro/src/utils/business-code.ts`

### 5.6 订单中心

- 后台创建订单
- 选择用户、上架商品和 SKU
- 自动生成订单号
- 保存联系人、游戏账号、昵称、区服、段位和服务要求
- 创建订单时固化商品、SKU、成交价格、套餐服务组成快照
- 限量库存下单扣减，取消订单返还
- 订单详情、商品快照、游戏资料、状态时间线

当前状态机：

```text
PENDING_PAYMENT 待支付
  → WAIT_ASSIGN 待派单
  → ASSIGNED 已派单
  → IN_SERVICE 服务中
  → COMPLETED 已完成
```

允许取消的状态：待支付、待派单、已派单。服务开始后暂不允许直接取消。

目前“确认收款”是后台人工状态操作，不是真实支付回调。

### 5.7 派单与接单

- 指定派单
- 公开抢单
- 自动筛选候选陪玩师
- 候选人匹配分、评分、当前进行中订单数
- 后台模拟接受、拒绝
- 所有候选人拒绝后任务结束
- 查询任务时自动判定超时
- 取消派单
- 拒绝、超时、取消后重新派单
- 接单成功后订单自动变为已派单
- 接单后陪玩师变为忙碌
- 订单完成或取消后释放陪玩师状态
- 派单候选人和操作时间线

候选筛选条件：

- 陪玩师已启用且审核通过
- 陪玩师配置了订单对应游戏且游戏资料启用
- 默认只选择工作状态为 AVAILABLE 的陪玩师
- 进行中订单数不能超过派单规则

同一个派单任务的接单使用数据库条件更新：只有 `DISPATCHING` 状态可被首位接受者更新为 `ACCEPTED`，后续接受请求失败。

## 9. 已知限制与风险

1. 当前使用 H2 文件数据库，不是生产数据库。
2. 真实支付、退款、结算尚未接入，“确认收款”为后台模拟操作。
3. 派单超时采用访问列表/详情时的惰性判定，没有独立调度任务。
4. 同一派单任务只能有一个接单赢家；但不同任务同时分配同一陪玩师的跨任务并发锁还需要加强。
5. 订单表支持多明细，但当前创建接口一期只创建一个 SKU 明细。
6. 订单商品快照已保护历史展示，但商品编辑会删除并重建 SKU，历史订单不要再依赖实时 SKU。
7. 旧的 `/api/business/order/{id}/assign` 可以绕过新派单流程，建议下一步删除或限制。
8. 文件上传目前主要根据扩展名校验，生产环境还需要 MIME、文件头、安全扫描和鉴黄。
9. 上传文件删除后没有孤儿文件清理任务。
10. 当前表结构没有系统性添加外键，业务完整性主要由服务层维护。
11. 后台页面部分沿用模板示例模块，业务菜单以动态后端菜单为准。
12. 项目生产配置仍需重新检查域名、跨域、JWT 密钥、数据库、上传目录和日志策略。
